# 한국어 이미지 객관식 VQA 성능 개선 기록

발표 준비용 실험 기록입니다. 목표 Kaggle 점수는 **0.97 이상**이며, 점수는 실제 제출 결과가 확인된 뒤에만 기입합니다. 원본은 [`(260827)_baseline_desktop5060ti.ipynb`](./(260827)_baseline_desktop5060ti.ipynb), **통합 실행 노트북은 [`(260922)_baseline_desktop5060ti.ipynb`](./(260922)_baseline_desktop5060ti.ipynb)**입니다. 노트북 안에 데이터·모델·학습·검증·제출 코드를 모두 담았습니다.

## 데이터와 실행 환경

- `data/train.csv`: 6,714문항, 정답 `a/b/c/d`가 대체로 균등합니다.
- `data/test.csv`: 6,714문항. 제출 형식은 `id,answer`입니다.
- `data/dev.csv`: 2,683문항에 최대 5개의 답 열이 있으나 답 사이의 불일치가 많습니다. 공식 점수 계산법을 확인하기 전에는 단일 정답 데이터로 취급하지 않습니다.
- 로컬 GPU: NVIDIA GeForce RTX 5060 Ti, VRAM 약 16GB.
- 실험 환경: Python 가상 환경 `baseline`, PyTorch `2.11.0+cu128`, PEFT `0.21.0`, bitsandbytes `0.50.2`. Qwen2.5는 Transformers `4.57.6`, Qwen3.5는 별도 `qwen35_libs`의 Transformers `5.17.0`을 사용합니다. Qwen3.5 실행 시 해당 경로를 `PYTHONPATH`에 지정합니다.
- 고정 검증 세트: 학습 CSV를 시드 42로 섞은 뒤 6,043개 학습 / 671개 검증으로 분리합니다. 모델 비교에는 같은 분할을 사용합니다.
- 대회 링크: [Kaggle SSAFY 16-2 AI](https://www.kaggle.com/competitions/ssafy-16-2-ai-9-21-9-28). 로그인된 대회 페이지에서 평가지표가 **Accuracy**임을 확인했습니다. 공개 데이터 증강, Hugging Face 사전 학습 VQA 모델, LoRA·양자화·미세 조정은 허용됩니다. 외부 API를 호출하는 추론과 테스트 정답 누출은 금지됩니다. 하루 제출 한도는 팀당 20회입니다.
- 제출 내역에서 원본 `submission.csv`의 공개 점수 **0.70837**을 확인했습니다. 팀의 별도 `submission_qwen35_9b_epoch1_fast.csv`는 **0.95829**입니다. 이 제출의 학습 설정과 추론 코드는 확인하지 않았으므로 아래 로컬 실험과 동일한 모델·방법으로 간주하지 않습니다.

원본 노트북에서 학습 200개 제한은 코드 셀 8, 384² 이미지 예산은 셀 10, 전체 입력에 대한 `labels` 복사는 셀 14, 검증 손실만 계산하는 부분은 셀 18, 프롬프트까지 포함한 디코딩과 실패 시 `a` 선택은 셀 20에 있습니다. 통합 노트북은 같은 단계 순서를 따르되 각 단계의 구현을 수정했습니다.

**주의:** 위 문제들이 Kaggle 0.70837점에 각각 얼마만큼 기여했는지는 아직 측정되지 않았습니다. 원본 노트북의 저장된 추론 로그에는 중간에 멈춘 실행도 포함돼 있어 해당 제출 파일과의 대응도 확인되지 않았습니다.

`1MP`는 최대 이미지 픽셀 예산 1,048,576을 뜻하며 실제 입력 이미지의 가로·세로가 1,024픽셀로 고정된다는 뜻이 아닙니다. 결과를 비교할 때는 모델·픽셀 예산·프롬프트·학습 여부를 함께 기록합니다.

원본 학습 이미지 6,714장 중 **191장만 1MP를 초과**합니다. 따라서 1MP에서 상한을 더 올리는 방식만으로는 대부분의 사진에서 추가 정보가 생기지 않습니다. 384² 픽셀보다 큰 이미지는 6,714장 전부이므로, 이 제한이 작은 글씨 인식에 큰 영향을 준다는 관찰과 일치합니다. 크기 집계는 통합 노트북의 발표용 분석 셀에서 재현합니다.

첫 100문항에서는 픽셀 예산만 달리했을 때 정확도가 0.78에서 0.90으로 올랐습니다. 전체 검증에서도 0.7615에서 0.8823으로 **0.1207, 즉 12.1%포인트** 올랐습니다. 두 실험은 이 저장소의 개선된 동일한 프롬프트·추론 코드에서 픽셀 예산만 바꾼 학습 전 비교입니다. 따라서 원본 노트북의 Kaggle 0.7점과 직접적인 단일 변경 효과로 해석하지 않습니다.

Qwen3.5-4B의 첫 자유 생성 평가에서는 답 대신 설명을 출력한 문항이 51개였습니다. 이때의 0.42는 한 글자 형식으로 파싱한 제출 가능 정확도이며, 모델의 이미지 이해 능력에 대한 공정한 비교값이 아닙니다. 다음 실험은 각 선택지의 첫 토큰 로그잇을 비교합니다.

토큰 점수 방식은 같은 100문항에서 0.80으로, Qwen2.5-VL-3B의 1MP 설정 0.90보다 낮았습니다. 따라서 Qwen3.5-4B 교체를 채택하지 않습니다. Qwen2.5의 정답 마스킹 학습 코드는 4개 이미지·옵티마이저 1단계의 실행을 완료했으며, 전체 학습은 이미지당 약 2초로 수 시간이 필요합니다.

원본+4영역 확대는 100문항에서 0.91이었습니다. 1MP 단독보다 2문항을 추가로 맞히고 1문항을 잃었으며, 추론 시간은 약 2.5배 길었습니다. 전체 적용의 이득은 작아 보입니다.

Qwen3.5-9B는 16GB GPU에서 4비트로 실행됐고, 첫 100문항에서 0.97을 기록했습니다. 그러나 671문항 전체 정확도는 **0.9463**이었습니다. 따라서 작은 표본의 0.97을 목표 달성으로 주장할 수 없습니다. Qwen2.5-VL-3B가 맞히고 9B가 틀린 사례는 16개, 두 모델 모두 틀린 사례는 20개입니다. 두 모델의 정답을 완벽하게 고르는 상한도 651/671=0.9702이므로, 0.97을 안정적으로 넘으려면 9B 자체의 오류를 줄이는 미세 조정이나 OCR 보조가 필요합니다.

9B 선택지 점수의 1·2위 차이가 1.0 미만일 때 Qwen2.5 답으로 바꾸는 단순 앙상블은 671문항에서 638/671=0.9508이었습니다. 검증 세트에서 정한 임계값이므로 과적합 위험도 있습니다. 이 방식만으로 0.97에 도달할 수 있다고 보지 않습니다. 재현용 분석은 통합 노트북의 발표용 분석 셀에 포함했습니다.

9B의 LoRA 학습은 1개 표본·1회 갱신을 완료하고 유효한 기울기를 확인했습니다. 하지만 Windows 실행 환경에서 핵심 연산 두 가지가 느린 PyTorch 대체 구현으로 실행되어 첫 단계에 약 49초가 걸렸습니다. 이 속도에서 6,043개 전체 학습은 현실적인 단기 실험이 아니므로, 가속 커널을 사용할 수 있는 별도 환경이나 이미 학습된 팀 모델의 재현 설정을 확보해야 합니다.

9B에 원본과 확대 영역 네 장을 동시에 넣자 첫 100문항 정확도가 0.97에서 0.90으로 내려갔습니다. 확대가 모든 모델에 도움이 된다는 가정은 성립하지 않았습니다. 이 설정을 전체 테스트 추론에 적용하지 않습니다.

글자·숫자 비교를 강조한 프롬프트는 첫 100문항에서 여전히 0.97이었고, 바뀐 예측 1개도 오답이었습니다. 전체 실험 전에 성능 향상 근거가 없어 기본 프롬프트를 유지합니다. `--prompt-style ocr`로 재현할 수 있습니다.

9B가 틀린 36문항과 맞힌 36문항에서 선택지 점수 대신 최대 32토큰의 답 생성을 비교했습니다. 정답 수는 두 방식 모두 36/72였고, 답이 바뀐 문항은 1개뿐이며 여전히 오답이었습니다. 단순 생성 전환은 채택하지 않습니다.

4문항 배치는 첫 100문항에 약 70초가 걸렸고 단일 추론의 예측과 모두 일치했습니다. 이 설정으로 테스트 6,714개에 대한 제출 파일을 생성합니다. `submission.partial.csv`를 매 배치 저장하므로 실행 중단 후 같은 명령으로 이어서 만들 수 있습니다. 파일 생성만으로 Kaggle 점수를 알 수는 없습니다.

전체 테스트 CSV가 완성되어 Kaggle에 제출됐으며 공개 점수는 **0.93952**였습니다. 동일 설정의 로컬 검증 0.94635보다 0.00683 낮습니다. 목표 0.97까지는 공개 점수 기준 **0.03048**이 더 필요합니다. 제출 파일은 [`../output/qwen35_9b_logits_full/submission.csv`](../output/qwen35_9b_logits_full/submission.csv)에 보존합니다. 이 결과는 새로운 모델·학습 없이 픽셀 예산과 추론 방식만 개선한 설정입니다.

EasyOCR(한국어·영어)을 671개 검증 이미지에 실행해 글자 인식 결과를 보존했습니다. OCR 문자열이 선택지에 나타나면 그 답으로 바꾸는 단순 규칙은 113개에 적용됐지만 정답을 0개 고치고 31개를 잃어 폐기했습니다. OCR 문자열을 Qwen3.5-9B 질문 앞에 넣는 방식은 오답 36개와 정답 36개를 의도적으로 고른 72개에서 8개를 고치고 2개를 잃었습니다. 그러나 고정 검증 세트에서 256개까지 비교하니 기본 모델 245개, OCR 추가 모델 236개로 악화됐습니다(1개 수정, 10개 손실). 오류 표본에 치우친 작은 실험 결과를 전체 성능으로 일반화할 수 없다는 사례이므로, 이 OCR 설정은 최종 제출에 사용하지 않습니다. 부분 결과는 [`../output/qwen35_9b_ocr_full.jsonl`](../output/qwen35_9b_ocr_full.jsonl)에 보존합니다.

9B QLoRA 1단계는 로컬 RTX 5060 Ti 16GB에서 실행됐지만 Windows에서 가속 커널이 없어 이미지당 약 49초였습니다. 전체 6,043개 학습은 이 속도로 약 82시간이므로 Kaggle GPU 경로를 통합 노트북에 추가했습니다. 대회 데이터 자동 탐색, 671개 검증 후 제출 파일 생성, 어댑터 저장 위치를 노트북에 명시했습니다. 아직 이 클라우드 학습은 실행하지 않았으며 0.97 달성을 주장하지 않습니다. [Unsloth의 Qwen3.5 학습 안내](https://unsloth.ai/docs/models/qwen3.5/fine-tune)는 9B BF16 LoRA에 약 22GB VRAM이 필요하고, 4비트 QLoRA는 양자화 차이로 권장하지 않는다고 설명합니다. 따라서 16GB 경로의 QLoRA는 실행 가능성 실험이며, 24GB 이상 GPU를 사용할 수 있다면 BF16 LoRA를 우선 비교해야 합니다.

클라우드 첫 학습은 `MAX_TRAIN_STEPS=250`, 누적 4회로 약 1,000장의 파일럿입니다. 모델을 학습할 때는 `RUN_TRAIN=True`, `RUN_EVAL=True`, `RUN_SUBMIT=False`로 시작하고, 검증 671개에서 이득이 있을 때 `MAX_TRAIN_STEPS=None`의 전체 학습을 검토합니다. 학습하지 않은 어댑터로 생성한 CSV나 일부 검증만으로 공개 0.97 달성을 주장하지 않습니다.

2026-09-22 계정의 Kaggle 새 노트북 설정 화면에서 선택 가능한 가속기는 **GPU T4 x2**와 TPU v5e-8뿐이었습니다. 인터넷은 켜져 있습니다. 단일 T4의 16GB 메모리만으로 9B BF16 LoRA는 실행할 수 없으므로, 현재 노트북의 9B 학습은 4비트 QLoRA 파일럿으로 준비했습니다. T4 두 장을 단일 32GB GPU로 간주하지 않습니다.

학습·테스트 이미지의 SHA-256 완전 동일 쌍은 24개, 간단한 dHash가 같은 쌍은 28개였습니다. 동일 이미지라도 대부분 질문이 다릅니다. 전체 테스트 6,714개에 비해 드물어 중복 암기만으로 목표에 도달하기 어렵습니다. 학습 이미지·질문·정답만 분석했고 테스트 정답은 사용하지 않았습니다.

## 후보 모델 검토

- [Qwen3.5-4B](https://huggingface.co/Qwen/Qwen3.5-4B)는 이미지와 텍스트 입력을 지원합니다. 공식 모델 카드의 OCRBench 수치는 85.0이지만, **이 대회의 정답률과 직접 비교할 수 없습니다**. 현재 환경의 `transformers 4.57.6`과 호환되는지 별도로 확인해야 합니다.
- [Qwen3.5-9B](https://huggingface.co/Qwen/Qwen3.5-9B)는 공식 OCRBench 수치가 89.2입니다. 16GB VRAM에서 4비트 추론 가능성과 실제 처리 시간을 먼저 확인합니다.
- [PaddleOCR-VL-1.6](https://huggingface.co/PaddlePaddle/PaddleOCR-VL-1.6)은 약 0.9B의 문서·문자 인식 모델입니다. 간판·포스터의 작은 글자가 주요 오류일 때 OCR 결과를 질문과 함께 넣거나 해당 영역을 확대하는 실험에 사용합니다. OCR 자체의 벤치마크 96.33%를 Kaggle 목표 0.97과 혼동하지 않습니다.

PaddleOCR-VL-1.6은 현재 로컬 환경에서 모델 초기화가 실패했습니다. Transformers 4.57.6, 5.0.0, 5.17.0 경로를 확인했으나 각각 마스킹 함수·RoPE 설정 호환 문제가 발생했습니다. 따라서 아직 OCR을 이용한 정확도 개선 결과는 없습니다. 실패한 실행을 성능 실험으로 간주하지 않습니다.

## 발표 시 사용할 근거

1. 원본의 학습 표본 수와 손실 계산 범위를 코드로 제시합니다.
2. 같은 671개 검증 세트에서 변경 전후 정확도와 파싱 실패를 비교합니다.
3. 오류를 작은 글씨, 다국어, 숫자·전화번호, 표·포스터, 순수 시각 추론 등으로 나눠 예시를 제시합니다.
4. 최종 설정의 Kaggle 제출 점수와 실행 시간, VRAM 사용량을 기록합니다.
5. 0.97 달성 여부와 무관하게 검증 점수와 Kaggle 점수의 차이 및 남은 한계를 명시합니다.
